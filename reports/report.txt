1. TITLE

Freelance Payment Escrow Using Blockchain


2. ABSTRACT

The Freelance Payment Escrow project is a blockchain-based application designed to provide a secure and transparent payment mechanism between clients and freelancers. The system uses a Solidity smart contract to hold the client's payment in escrow until the freelancer completes the assigned work and the client approves it.

The project implements a complete workflow consisting of escrow creation, funding, work initiation, work submission, approval, and payment release. The application uses a React-based frontend, Ethers.js for blockchain interaction, MetaMask for wallet connectivity, and Hardhat Local Network for smart contract development and testing.

By using a smart contract, the payment process is controlled by predefined rules instead of relying completely on manual payment handling. The project demonstrates how blockchain technology can be applied to freelance platforms to improve transparency, trust, and payment security.


3. INTRODUCTION

Freelancing involves transactions between clients and freelancers who may not have an established level of trust with each other. A common problem is that clients may hesitate to pay before receiving the work, while freelancers may hesitate to start work without payment security.

The Freelance Payment Escrow system addresses this problem by using a blockchain smart contract as an escrow mechanism. The client deposits the agreed amount into the smart contract. The freelancer can start and submit the work after the required conditions are satisfied. Once the client approves the submitted work, the smart contract releases the payment to the freelancer.

The project is developed and tested on a Hardhat Local blockchain network. MetaMask is used to connect different blockchain accounts representing the client and freelancer.


4. PROBLEM STATEMENT

Traditional freelance payment systems may involve payment delays, trust issues, third-party intermediaries, transaction disputes, and lack of transparency.

The main problem is to design a system where:

- The client's payment is protected before the work is completed.
- The freelancer can verify that the payment has been funded.
- Work progress follows a controlled sequence.
- Payment is released only after client approval.
- Blockchain transactions provide transparency.
- The system reduces dependency on manual payment processing.

9. SYSTEM WORKFLOW

The complete workflow of the system is:

FUND
  ↓
START WORK
  ↓
SUBMIT WORK
  ↓
APPROVE
  ↓
PAYMENT RELEASED
  ↓
VERIFY


Detailed workflow:

Step 1: Create Escrow

The client enters the freelancer's wallet address and project title. The smart contract creates a new escrow project and assigns a unique project ID.

Step 2: Fund Escrow

The client deposits the agreed amount into the smart contract. The contract holds the payment securely.

Project status changes to:

FUNDED


Step 3: Start Work

The assigned freelancer connects their wallet and starts the project.

Project status changes to:

IN_PROGRESS


Step 4: Submit Work

After completing the assigned work, the freelancer submits the work through the frontend.

Project status changes to:

SUBMITTED


Step 5: Approve Work

The client reviews the submitted work and approves it.

Step 6: Release Payment

After approval, the smart contract transfers the escrowed amount to the freelancer.

Project status changes to:

COMPLETED


Step 7: Verify

The project details and contract balance can be loaded from the frontend to verify that the workflow completed successfully.


10. PROJECT STATUS FLOW

The smart contract uses project states to control the workflow.

CREATED
   |
   v
FUNDED
   |
   v
IN_PROGRESS
   |
   v
SUBMITTED
   |
   v
COMPLETED


Meaning of each state:

CREATED:
The escrow project has been created but has not yet been funded.

FUNDED:
The client has deposited the agreed amount into the escrow contract.

IN_PROGRESS:
The assigned freelancer has started the work.

SUBMITTED:
The freelancer has submitted the completed work.

COMPLETED:
The client has approved the work and the payment has been released.

12. IMPORTANT SMART CONTRACT FUNCTIONS

createEscrow()

Purpose:
Creates a new freelance escrow project.

Inputs:
- Freelancer wallet address
- Project title

Output:
- Project ID


fundEscrow()

Purpose:
Allows the client to deposit the agreed payment into the smart contract.

Input:
- Project ID

Payment:
- ETH sent with the transaction


startWork()

Purpose:
Allows the assigned freelancer to start the project.

Input:
- Project ID


submitWork()

Purpose:
Allows the assigned freelancer to submit the completed work.

Input:
- Project ID


approveAndReleasePayment()

Purpose:
Allows the client to approve the submitted work and release the escrow payment.

Input:
- Project ID

Result:
- Payment is transferred to the freelancer.
- Project status becomes COMPLETED.


getEscrowDetails()

Purpose:
Retrieves the stored project details.

The function provides information such as:

- Project ID
- Client address
- Freelancer address
- Escrow amount
- Project status
- Additional project information


getContractBalance()

Purpose:
Returns the amount of ETH currently held by the escrow contract.


getNextProjectId()

Purpose:
Returns the next project ID available for creation.
